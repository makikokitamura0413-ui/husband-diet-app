# カロリー記録（夫用ダイエット・カロリー管理アプリ）

毎日の **摂取カロリー・総消費カロリー・体重** をスマホで簡単に記録し、カレンダーとグラフで確認するための MVP です。

## 画面

| 画面 | できること |
|---|---|
| はじめに / 設定 | 性別・年齢・身長・体重・日常活動レベルを入力。バックアップ保存・復元 |
| ホーム | 今日の体重・摂取・総消費・収支・運動消費。食事／運動／体重の追加ボタン |
| カレンダー | 月間カレンダーに各日の摂取（上）・総消費（下）。色で収支、●で運動日 |
| 日付詳細 | その日の数値・総消費の内訳・食事一覧・運動一覧（タップで編集、×で削除） |
| 食事入力 | 最上部の「食事を自由入力」で食事名＋kcalをそのまま記録（マイメニューには登録しない）。その下で 朝昼夕間食 → 料理名入力で簡易食品データから推定カロリー。量×0.5〜。「自分でメニューを登録」でマイメニュー（名前＋kcal）を登録・編集・削除 |
| 運動入力 | 種類＋時間 → 推定消費カロリー |
| 月間サマリー | 総摂取・総消費・収支・1日平均・運動日数・月初/月末体重・体重変化 |
| 体重グラフ | 実測体重と7日移動平均を同じグラフに表示 |

## 計算方法（すべて推定値・目安）

```
総消費 = 基礎代謝 + 日常活動 + 運動の追加消費
基礎代謝   = (0.0481×体重 + 0.0234×身長 − 0.0138×年齢 − 定数) × 1000 / 4.186
             定数：男性 0.4235 / 女性 0.9708（国立健康・栄養研究所の式）
日常活動   = 基礎代謝 × (活動係数 − 1)   活動係数：低い1.5 / ふつう1.75 / 高い2.0
運動       = (METs − 1) × 体重kg × 時間h × 1.05（安静分を除いた追加消費）
収支       = 摂取 − 総消費（マイナス＝消費が多い）
7日平均    = その日を含む直近7日間の体重記録の平均（7日分なければある分で平均）
月間集計   = 摂取・消費・収支・平均は「食事を記録した日」を対象
```

体重はその日以前の最新の記録を基礎代謝に使います（記録がなければ設定の体重）。

## 起動方法

```bash
npm install
npm run dev      # http://localhost:5173 （同じWi-Fiのスマホからは表示される Network のURLで）
npm test         # 計算ロジックのテスト
npm run build    # dist/ に本番ビルド
```

### スマホで毎日使う（GitHub Pages）

1. GitHub のリポジトリ設定 → Pages → Source を **GitHub Actions** にする
2. `main` ブランチに push すると自動で公開されます
3. スマホで公開URLを開き、「ホーム画面に追加」するとアプリのように使えます

## データ

データはその端末のブラウザ（localStorage）に保存されます。サーバーには送信しません。
マイメニューも同じ保存データ（`customFoods`）に入り、バックアップにも含まれます。
機種変更・ブラウザのデータ削除に備えて、設定画面の「バックアップを保存」で JSON を保存できます。

## データの保護（v0.2.0〜）

データはこの端末のブラウザの保存領域（localStorage）に保存します。サーバーには送信しません。

| キー | 内容 |
|---|---|
| `husband-diet-app:v1` | 本データ（設定・体重・食事・運動・マイメニュー）。**キー名・形式は最初の版から変えていない** |
| `husband-diet-app:v1:snapshots` | 端末内の自動の控え（毎日最初の起動時・復元／全削除の直前） |
| `husband-diet-app:meta` | 最終バックアップ日時と方法 |
| `husband-diet-app:probe` | 初回かどうかを確かめるための書き込み確認 |
| `husband-diet-app:v1:unreadable:<日時>` | 読めなかった本データを、復元で置き換える前に写したもの |

| 対策 | 防げること | 防げないこと |
|---|---|---|
| 保護モード | 読み込めないときに初期設定で上書きしてしまう事故 | ― |
| 書き込みの確認・他タブの検知 | 保存失敗に気づかない／古いタブでの上書き | ― |
| 端末内の控え | 操作ミス・不具合による上書き | **Safari の Webサイトデータ消去（一緒に消える）** |
| 永続化の申請（`navigator.storage.persist()`） | 容量不足などによるブラウザの自動削除を受けにくくする | **ユーザーによるデータ消去**（保証ではない） |
| PWA（ホーム画面に追加） | Safari の「7日間使わないと消える」制限 | ユーザーによるデータ消去 |
| **「ファイル」へのバックアップ** | **上記すべて（端末の外に残る唯一の控え）** | ファイルを保存していない期間の記録 |

- 保存データを読み込めないときは「保存データを確認できませんでした。データ保護のため、新しいデータで上書きする操作を停止しています。」と表示し、初期設定や記録の保存を止めます。元データはファイルに書き出せます。
- 復元は、ファイルの形式・版・中身を検査し、確認画面（復元する内容と現在の件数の比較）を経てから行います。置き換える前の状態は端末内の控えに残します。
- Service Worker はアプリ本体のファイルをキャッシュするだけで、記録データには触れません。
- ホーム画面に追加したアプリは、iPhone では **Safari とは別の保存場所** です。移すときは Safari で「バックアップを保存」→ ホーム画面のアプリで「バックアップから復元」します。

### iPhone 実機での確認手順

1. 設定 →「バックアップを保存」→ 共有シートで「"ファイル"に保存」→ 保存先を選んで保存
2. 設定 →「バックアップファイルを確認」→ いま保存したファイルを選ぶ
3. 「✓ 復元に使えるバックアップです」「現在のデータと完全に一致しています」と表示されれば成功（確認は読み取りのみ）
4. 設定の「最終バックアップ」に日時と「共有シート」が表示されていること

## 技術構成

Vite + React + TypeScript（外部ライブラリなし・グラフは自前SVG）、Vitest。

```
src/lib/        計算・型・データ検査・バックアップ形式・store（画面に依存しない）
src/lib/storage 保存先の差し替え口（StorageDriver。将来 iOS アプリ化するときはここを差し替える）
src/platform/   ファイル保存（共有シート）・永続化要求など端末の機能
src/screens, components  画面
sw/             Service Worker の元（ビルド時に sw.js を生成）
```
